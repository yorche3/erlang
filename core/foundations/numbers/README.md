# Numbers — Erlang

Implementación de la especificación [04_Numbers](https://yorche3.github.io/programming_languages/core/foundations/04_Numbers/) en **Erlang**, utilizando **rebar3** como sistema de compilación y **EUnit** para las pruebas unitarias.

Este módulo implementa algoritmos fundamentales (suma de los primeros N naturales, factorial, Fibonacci, MCD, MCM) utilizando dos enfoques: **recursivo directo** y **recursivo con acumulador (tail recursion)**.

## 📝 Notas de implementación / Implementation Notes

### 🔁 Sobre recursión con acumulador y Tail Call Optimization (TCO) / On recursion with accumulator and Tail Call Optimization (TCO)

**ES:**

*Tail recursion* ocurre cuando la llamada recursiva es la última acción que ejecuta una función/método; después de la llamada no hay más instrucciones, la función devuelve el resultado de la llamada recursiva. La recursión con acumulador consigue esto pasando el estado previo como parámetro a cada llamada, sin dejar trabajo pendiente en la pila.

**Erlang/OTP sí garantiza TCO.** La máquina virtual BEAM está diseñada específicamente para optimizar llamadas de cola. Esto es fundamental en Erlang, donde la concurrencia masiva (cientos de miles de procesos) depende de que los bucles se implementen como recursión de cola sin consumir pila adicional. Cualquier compilador Erlang (erlc) genera automáticamente código de salto (`jump`) en lugar de llamada (`call`) cuando detecta una llamada en posición de cola.

La implementación con acumulador es completamente funcional y eficiente en Erlang. A diferencia de otros lenguajes donde la versión con acumulador es solo un puente conceptual, en Erlang es la forma idiomática y recomendada de implementar iteración.

**EN:**

*Tail recursion* occurs when the recursive call is the last action that runs a function/method; after the call there are no more instructions, the function returns the result of the recursive call. Recursion with accumulator gets this by passing the previous state as a parameter to each call, without leaving any pending work on the stack.

**Erlang/OTP does guarantee TCO.** The BEAM virtual machine is specifically designed to optimize tail calls. This is fundamental in Erlang, where massive concurrency (hundreds of thousands of processes) depends on loops being implemented as tail recursion without consuming additional stack. Any Erlang compiler (`erlc`) automatically generates jump code instead of call code when it detects a call in tail position.

The accumulator implementation is fully functional and efficient in Erlang. Unlike other languages where the accumulator version serves only as a conceptual bridge, in Erlang it is the idiomatic and recommended way to implement iteration.

### 🧵 Sobre cláusulas múltiples y pattern matching / On multiple clauses and pattern matching

**ES:**

En Erlang, una función puede tener **múltiples cláusulas** separadas por `;`. El intérprete evalúa las cláusulas en orden y ejecuta la primera que hace match con los argumentos. Esto permite expresar casos base y recursivos sin usar condicionales `if`/`else`.

```erlang
% Pattern matching en parámetros + cláusulas múltiples
factorial_rec(0) -> 1;   % Caso base: N = 0
factorial_rec(N) -> N * factorial_rec(N - 1).   % Caso recursivo
```

Las cláusulas de una misma función deben definirse **juntas y contiguas**; no se puede intercalar código de otra función entre ellas.

**EN:**

In Erlang, a function can have **multiple clauses** separated by `;`. The interpreter evaluates clauses in order and executes the first one that matches the arguments. This allows expressing base cases and recursive cases without using `if`/`else` conditionals.

```erlang
% Pattern matching on parameters + multiple clauses
factorial_rec(0) -> 1;   % Base case: N = 0
factorial_rec(N) -> N * factorial_rec(N - 1).   % Recursive case
```

All clauses of the same function must be defined **together and contiguously**; you cannot interleave code from another function between them.

### 🔢 Sobre `div` y `rem` / On `div` and `rem`

**ES:**

Erlang usa operadores distintos para la división:
- **`div`**: División entera (descarta el resto). Ej: `10 div 3` → `3`.
- **`/`**: División real (devuelve float). Ej: `10 / 3` → `3.333...`.
- **`rem`**: Resto de la división entera. Ej: `10 rem 3` → `1`.

El algoritmo de Euclides para GCD usa `rem`, mientras que LCM usa `div`.

**EN:**

Erlang uses different operators for division:
- **`div`**: Integer division (truncates remainder). E.g.: `10 div 3` → `3`.
- **`/`**: Real division (returns float). E.g.: `10 / 3` → `3.333...`.
- **`rem`**: Remainder of integer division. E.g.: `10 rem 3` → `1`.

Euclid's algorithm for GCD uses `rem`, while LCM uses `div`.
